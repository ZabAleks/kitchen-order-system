1. Какая команда оказалась самой непонятной до практики?

Ответ: Команды `git merge` или `git revert`. До практики было сложно представить, как Git понимает, какие строки кода важнее, и как он "склеивает" историю из разных веток. Также пугает выход из редактора Vim при слиянии.

2. Почему важно настраивать user.name/email перед коммитами?

Ответ: Это цифровой "автограф" разработчика. В Git история изменений неизменяема. Если не настроить эти данные:

    Невозможно будет понять, кто именно внес баг или полезную фичу (особенно в команде).
    Сервисы вроде GitHub не смогут связать коммиты с твоим профилем (не будет "зеленых квадратиков" активности).
    В корпоративной среде аудит безопасности не пропустит анонимный код.

3. В каком случае git revert безопаснее, чем git reset?

Ответ: `git revert` безопаснее при работе с удаленным репозиторием (публичными ветками).

    `git reset` удаляет коммиты из истории, как будто их не было. Если кто-то другой уже скачал эти коммиты, у него возникнет критическая ошибка при обновлении.
    `git revert` не удаляет старое, а добавляет новое (отменяющее) изменение. Это сохраняет целостность истории, и твои коллеги не столкнутся с проблемами при `git pull`.

4. Как .gitignore мог бы спасти проект от утечки данных?

    Ответ: В файлах вроде `.env` или `config.json` часто хранятся пароли от баз данных, API-ключи или токены доступа. Если случайно отправить их в публичный репозиторий, их тут же обнаружат боты-сканеры. `.gitignore` гарантирует, что такие файлы физически не попадут в индекс Git, даже если ты случайно введешь `git add .`.
